# Review-workspace programme

The self-assessment workspace stores versioned local JSON under the ignored `runtime-data` directory. `/api/collaboration` supports snapshot, lock, comment, comment resolution, reviewer override, import and guided self-assessment actions, and the cockpit's Obligation Tracker uses two more: `evidence_view` returns the tracker for a cockpit system and is read-only (it saves nothing and never sets a stored file aside; the cockpit posts it on each classification), and `evidence` saves one obligation graph item's evidence state, owner and reviewed-on date with a revision (see [API.md](API.md#obligation-tracker) and [ADR 0006](adr/0006-evidence-model.md)). Evidence records are kept in the workspace's `evidence` list, keyed by cockpit system, obligation and actor; each save adds an `evidence_updated` event to the activity. The browser surface supports local import and export; the export starts with `draftNotice`, which an import ignores. An import replaces the review cells but keeps the activity trail: earlier entries stay, the file's entries the trail lacks follow, and an `imported` event records the actor and the number of entries added. A file with an `evidence` key replaces the evidence records; a file without one, such as one exported before the tracker existed, keeps them. The route accepts same-origin `application/json` POSTs only (see DEPLOYMENT.md).

Each save writes the workspace to a temporary file in `runtime-data` and then renames it over `collaboration-workspace.json`, so a failed write leaves the previous file as it was. A stored file the bridge cannot use, because it is not a valid workspace (cut off or edited by hand) or because it was built for another inventory (for example after an example was added, removed or renamed), is not deleted: it is renamed to `collaboration-workspace.unreadable-<UTC time>.json` or `collaboration-workspace.stale-<UTC time>.json` in the same directory, and a new workspace is saved whose activity starts with a `recovered` event naming that file. A stale file's evidence records do not depend on the inventory, so they are carried into the new workspace and the `recovered` event counts them in `evidenceCarried`; an unreadable file carries nothing. A stale file cannot be imported back; its reviews have to be entered again against the current inventory. A file saved before the tracker existed loads with no evidence. A build from before the tracker drops the evidence on its next save, so export the workspace before going back to one. Lock times are compared in UTC, and a lock time without a time zone counts as UTC. Every action but `evidence_view` holds an exclusive lock on `collaboration-workspace.json.lock` in `runtime-data` from the load through the save, so two bridge processes cannot both pass the same revision check; the lock file holds nothing. A reviewed-on date may not be after the bridge's local calendar date.

The deterministic classifier result is immutable in each review cell. Reviewer overrides are separate fields. Workflow runs record the exact definition snapshot, classifier version, source versions, artifacts, decisions and audit events. Draft packets remain synthetic, local and human-review gated.

Run `uv run --isolated --extra dev ruff check .`, `uv run --isolated --extra dev ruff format --check .`, `uv run --isolated --extra dev pytest -q`, and `cd web && npm test && npm run build`.
